\section{Introduction}
\label{sec:intro}

Maintenance of aircraft engines is either scheduled at fixed intervals or
triggered by observed condition. Fixed intervals replace parts that still
have life left, while waiting for a fault risks a failure in service.
Predicting the remaining useful life (RUL) of an engine, the number of
operating cycles left before it fails, lets maintenance be planned close to
the point where it is actually needed. The cost of an error is asymmetric:
predicting too much remaining life risks an in-service failure, while
predicting too little only brings maintenance forward.

The NASA Commercial Modular Aero-Propulsion System Simulation (C-MAPSS)
data~\cite{saxena2008damage} are the standard public benchmark for this
task. Each engine is simulated from a healthy state with unknown initial
wear, and 21 sensors and three operating settings are recorded once per
cycle. Training engines run to failure; test engines are cut off at an
unknown point, and the true RUL is given only at their last observed cycle.
We work on the FD001 subset, which has one operating condition and one
fault mode.

The report asks one question: on this benchmark, can a network that learns
from the raw sensor history match or beat features engineered by hand? We
answer it in two phases under one protocol. In Phase 1, from the 14
informative sensors in FD001, we compute within each engine rolling means,
standard deviations and least squares slopes over three window lengths and
a health index learned by linear regression, and train Elastic Net, Random
Forest and XGBoost on them. In Phase 2, an LSTM, a temporal convolutional
network and a Transformer encoder read 30-cycle windows of the same sensors
directly, and two hybrids combine the windows with the engineered features.
Every model is trained on RUL capped at 125 cycles and tuned with five-fold
cross validation grouped by engine, so that no engine contributes rows to
both sides of a split. The test set is used once per phase, after every
hyperparameter and the choice of model are frozen.

The contributions of this report are:
\begin{itemize}
\item an engine-level evaluation protocol for FD001 in which every scaler
and feature statistic is refitted inside each fold, early stopping uses
engines held out of the fold's training engines, and the test set is scored
once, with errors reported separately for engines near failure;
\item a comparison of three regressors on raw and engineered features,
showing that the engineered features and the move from linear to tree
models each improve the RMSE by several cycles, and an analysis of what the
tree ensembles rely on;
\item three sequence networks and two hybrids evaluated under the same
protocol over five seeds, showing that the selected Transformer ties
XGBoost on engineered features on the test set, is more accurate close to
failure, and is not improved by adding the engineered features;
\item single-factor ablations of the window length, target cap,
regularisation, inputs and hybrid branches, and a comparison of every model
with published FD001 results under matched label clipping.
\end{itemize}
